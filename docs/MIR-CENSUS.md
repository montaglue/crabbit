# MIR census — what the imported `mir` dialect contains today

Date: 2026-10-27. Backend: `target/debug/libcrabbit.so` built from this
tree (toolchain `nightly-2026-04-03`, dialect-mir/mir-lower at cuda-oxide
rev `c8ad357`). Produced by the `mir-census` pass
(`crates/mir/src/passes/mir_census.rs`), which runs on every module right
before `lower-dialect-mir` when `CRABBIT_MIR_CENSUS=<file>` is set and
appends one JSON object per module to that file. The tables below are
rendered from those JSON lines; the JSON (per-function histograms, every
callee) is the complete record and is regenerated by the commands in
[Commands](#commands).

Six crates: three backend-tests fixtures (host, aarch64 Linux) and three
kernel-corpus device crates (NVPTX kernels). A device crate yields two
modules: `rust_crate` (the host side, which for these `no_std` crates is
only the `#[panic_handler]`) and `rust_kernels` (the `__crabbit_kernel_*`
functions). Device crates and the fixtures are compiled with
`-Coverflow-checks=off` (the corpus and backend-tests recipes), so rustc's
MIR carries no overflow `Assert`s to begin with; bounds checks and other
`Assert` terminators are unaffected by that flag.

**Deviation from the requested set.** `crates/backend-tests/fixtures/llama-rms-norm`
cannot be compiled by any backend: its manifest points `crabbit-device` at
`../../../crates/crabbit-device`, which does not exist (`crates/crates/`),
and with the path redirected to the only copy in the tree
(`fixtures/vendor/crabbit-device`) rustc stops at
`E0432: unresolved imports crabbit_device::DeviceSlice, DisjointSlice,
block, kernel, math, thread` — the fixture is from the AMDGPU-era device
API and its test is `#[ignore]`d for that reason. The census here uses the
kernel-corpus `rms_norm` device crate in its place (the same algorithm
family: strided sum of squares, block reduction, `rsqrt`, strided
normalize). Nothing in the repository was modified to get there; the
attempt was made on a scratch copy.

## What this says about the importer

Everything below is read off the tables; nothing is inferred from the
importer's source.

- **None of dialect-mir's Rust-semantic ops are emitted.** Across all six
  crates (ten modules, 44,909 ops) the `mir.*` vocabulary in use is 27
  kinds — 26 in the host crates, the kernels add `float_constant`:
  `alloca`/`load`/`store`, `constant`/`float_constant`, the arithmetic,
  bit and compare ops, `cast`, `call`, `goto`/`cond_br`/`return`/
  `unreachable`. Zero occurrences of `mir.construct_struct/
  tuple/array/slice/enum`, `mir.insert_field`/`extract_field`/`undef`,
  `mir.field_addr`/`array_element_addr`/`ptr_offset`/`ref`, `mir.assert`,
  `mir.checked_add/sub/mul`, `mir.get_discriminant`/`set_discriminant`/
  `enum_payload`, `mir.memcpy`/`memmove`, `mir.storage_live/dead`,
  `mir.assign`, `mir.cmp`.
- **The pre-lowered forms are already LLVM-dialect ops at the mir level:**
  14.6% of sudoku-solver's ops (3,157 of 21,687) and 12.8% of
  hashmap-aarch64's (2,811 of 21,936) are `llvm.*` before
  `lower-dialect-mir` runs. By kind (sudoku / hashmap): `llvm.insert_value`
  977 / 766, `llvm.undef` 809 / 596, `llvm.extract_value` 593 / 492,
  `llvm.gep` 371 / 590, `llvm.addressof` 213 / 165, `llvm.bitcast` 156 / 61,
  `llvm.lshr` 24 / 133, `llvm.icmp` 14 / 2, `llvm.call` 0 / 6. The kernels
  carry 5–9 `llvm.*` ops each (`llvm.gep` and `llvm.addressof`).
- **Aggregates: 0 `construct_*` against 578 (sudoku) and 450 (hashmap)
  undef→insert chains**, i.e. every aggregate value is built the
  `llvm.undef` + `llvm.insert_value` way (and read back with
  `llvm.extract_value`); together those three kinds are 11.0% and 8.5% of
  all ops. The four kernels build no aggregate values at all (0 / 0).
- **Assertions: 0 `mir.assert`, while the host crates call into
  `core::panicking` 40 (sudoku) and 31 (hashmap) times** —
  `panic_nounwind_fmt` 20 / 9, `panic` 8 / 5, `panic_fmt` 8 / 1,
  `assert_failed*` 3 / 15, `panic_nounwind` 1 / 1 — and contain 153 / 110
  `mir.unreachable`. Checked arithmetic is 0 everywhere, consistent with
  `-Coverflow-checks=off` on every compile here.
- **Memory model: one alloca per local.** `mir.alloca` is 17.3% / 17.5% of
  all host ops (3,744 / 3,848), and alloca+load+store together are 56.3% /
  57.9%. Per function: median 8.5 / 8.0 allocas, max 404
  (`alloc::str::join_generic_copy`) / 262 (`hashmap_aarch64::main`); only
  5 / 2 functions have none. The kernels are single functions of 153–426
  ops with 27–71 allocas (17–18%).
- **Calls: the standard library is still visible as calls, not inlined,
  at this level.** sudoku-solver: 507 calls to 268 distinct callees, 428 of
  them (84%) into `core`/`alloc`/`std` families — `core::ptr` 93 (of which
  `drop_in_place::<…>` 82), `core::slice` 51, `alloc::vec` 40,
  `core::panicking` 40, `core::iter` 33, `alloc::raw_vec` 25, `core::ops`
  18, `core::str` 18, `core::option` 13; iterator/slice/ops/option
  machinery alone is 115 calls, and 21 calls are
  `*::precondition_check` helpers. hashmap-aarch64: 391 calls to 226
  callees, 344 (88%) into `core`/`alloc`/`std`/`hashbrown` —
  `hashbrown::raw` 61, `core::ptr` 48, `core::core_arch` 33 (the NEON
  wrappers hashbrown's `Group` uses: `vld1_u8` 13, `vreinterpret_*` 6,
  `vcltz_s8`/`vdup_n_u8` 2 each, lane/compare/or/store helpers for the
  rest), `core::panicking`
  31, `core::fmt` 21, `std::hash` 20, `hashbrown::map` 19, `core::hash`
  17; 6 calls are indirect. `memcpy`/`memcmp`/`memset`/`memmove` appear as
  plain calls: 7 (sudoku) and 25 (hashmap). Kernel modules call only the
  NVVM intrinsic declarations (`llvm_nvvm_barrier0`, the `read_ptx_sreg_*`
  reads, `fmax`/`ex2_approx`/`rsqrt_approx`/`atomic_add_gen_i`): 6–11
  calls per kernel.
- **Loops** (natural loops over the block CFG, back edges merged per
  header): 20 loops in 14 functions (sudoku, all depth 1); 20 in 16
  (hashmap, max depth 2); softmax 5, gemm_tiled 2 (nested, depth 2),
  histogram 1, rms_norm 3. Each device crate's `rust_crate` module is the
  `#[panic_handler]` (`rust_begin_unwind`: 2 blocks, 4 ops, the `loop {}`).

For the thin-importer plan this fixes the volumes per construct in this
corpus: the aggregate rewrite (`construct_*`/`insert_field`/
`extract_field`) touches ~2,400 / ~1,850 ops per host crate, the place
rewrite (`field_addr`/`array_element_addr`/`ptr_offset` for today's
`llvm.gep` + `llvm.bitcast` + part of `mir.cast`) ~530 / ~650, the
`mir.assert` rewrite 40 / 31 panic call sites, and `mir.memcpy` 7 / 25
call sites; the kernels are affected only by the place rewrite (5–9 ops
each).

## Commands

Backend from this tree (`cargo build -p crabbit`, debug profile), then:

```sh
REPO=~/projects/montaglue/crabbit
OUT=<dir for the JSON lines>; SCRATCH=<a cargo target dir outside the repo>

# backend-tests fixtures (the backend_smoke.rs recipe; --release for the two host fixtures)
for spec in sudoku-solver:crabbit-sudoku-solver hashmap-aarch64:hashmap-aarch64; do
  f=${spec%%:*}; bin=${spec#*:}
  ( cd $REPO/crates/backend-tests/fixtures/$f &&
    CRABBIT_MIR_CENSUS=$OUT/$f.jsonl CARGO_TARGET_DIR=$SCRATCH/fixture-$f \
    cargo rustc --manifest-path Cargo.toml --bin $bin --release -- \
      -Zcodegen-backend=$REPO/target/debug/libcrabbit.so -Coverflow-checks=off -Csave-temps )
done
# llama-rms-norm (same recipe, debug profile, --bin crabbit-llama-rms-norm) fails before
# codegen: see the deviation note above.

# kernel-corpus device crates (the tools/arms.py::_cargo_rustc recipe)
export RUSTUP_TOOLCHAIN=nightly-2026-04-03
for spec in softmax:softmax-device gemm_tiled:gemm-tiled-device histogram:histogram-device rms_norm:rms-norm-device; do
  k=${spec%%:*}; pkg=${spec#*:}; m=~/projects/montaglue/kernel-corpus/kernels/$k/device/Cargo.toml
  cargo clean --manifest-path $m --target-dir $SCRATCH/corpus-$k --release -p $pkg
  CRABBIT_MIR_CENSUS=$OUT/$k.jsonl cargo rustc --manifest-path $m --lib --release \
    --target-dir $SCRATCH/corpus-$k -- -Zcodegen-backend=$REPO/target/debug/libcrabbit.so -Coverflow-checks=off
done
```

Each JSON line is `{"crate", "module", "functions": {symbol: {...}},
"totals": {...}}`; per function and in `totals`: `blocks`, `ops`,
`op_kinds`, `calls` (demangled callee → count), `call_families`,
`allocas`, `asserts`, `checked_arith`, `aggregates` (`construct`,
`undef`, `insert`, `undef_insert_chains`), `loops`, `max_loop_depth`;
`totals` adds `functions`, `declarations`, `other_top_level` and
`ops_by_dialect`. The tables below list histogram entries by count
(descending, ties by name). `crabbit_mir::passes::mir_census::Census`
renders the same per-module tables through its `Display` impl.
